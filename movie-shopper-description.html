Main Features

1. Movie Search

  • Search is triggered after a minimum of 3 characters to reduce unnecessary requests
  • Debounced input ensures queries are only sent when the user pauses typing, improving performance and user experience
  • Results are retrieved from the local database when available, with fallback to TMDB for extended coverage
  • Optimized for fast, responsive lookups with minimal backend load

2. Movie Details

  • Displays comprehensive movie information including cast, reviews, and metadata
  • Missing data is lazy-loaded from external APIs to avoid unnecessary initial load
  • Combines local persistence with external enrichment for a complete user experience

3. Advanced Search

  • Supports filtering across multiple dimensions for precise querying
  • Filter options include:
    • Year of release
    • Rating
    • Popularity
    • Genres
  • Designed to support complex queries while maintaining performance

4. Catalog

  • Enables full browsing of the movie database
  • Supports paging, sorting, and editing of entries
  • Concurrency-safe updates implemented using ETag to prevent conflicting changes
  • Optimized for scalability when handling large datasets

5. Favorites & User Flow

  • Users can add or remove movies as favorites directly from the UI
  • When authenticated, users gain access to a dedicated profile/favorites page
  • Favorites are persisted per user for a personalized experience
  • From the profile/favorites page, users can add movies to a cart
  • When items are added to the cart, a badge is displayed on the cart icon showing the current number of items
  • This creates a seamless flow from discovery → favorites → cart

6. Actor Pages

  • Dedicated pages for actors with detailed information
  • Includes filmography with sorting capabilities
  • Provides easy navigation between actors and related movies

7. Authentication

  • Authentication handled via Google Login
  • Secure access to user-specific features such as profile, favorites, and cart
  • Follows modern authentication practices (OAuth2/OpenID Connect)

8. Cart

  • Supports adding selected movies from the favorites/profile page
  • Cart state is reflected in real-time via a badge indicator in the UI
  • Designed for future extensions such as checkout, payments, or rentals

CI/CD & Deployment

  • Automated backend pipeline triggered on merge to main after approved Pull Request
  • Build, test, and deployment to Azure App Service
  • Frontend pipeline deploying to Azure Static Web Apps
  • Environment-specific configuration handled via secure variables

Azure Resources

  • Azure App Service for hosting backend API
  • Azure Static Web Apps for frontend hosting
  • Azure SQL Database for persistent storage
  • Azure Key Vault for secrets and credentials
  • Azure Application Insights for monitoring and logging
  • Azure Storage Account for supporting infrastructure

Architecture & Design Principles

  • Built using Clean Architecture to ensure clear separation of concerns and long-term maintainability
  • Applies Domain-Driven Design (DDD) with focus on core business concepts, aggregates, and ubiquitous language
  • Implements CQRS to separate read and write concerns, improving scalability and flexibility
  • Strict separation between Domain, Application, Infrastructure, and Presentation layers
  • Dependency inversion ensures the domain remains independent of frameworks, databases, and external systems
  • Encapsulation of business rules within domain entities to enforce invariants and consistency
  • Favors composition over inheritance to promote flexibility and reduce coupling
  • Supports unit and integration testing through clear boundaries

Configuration Management

Configuration is structured using strongly typed option classes mapped from appsettings.json. These are injected using IOptions<T>, ensuring a clean and maintainable approach to configuration handling.

  • Type-safe and easy to maintain, reducing runtime errors caused by invalid configuration values
  • Centralized and consistent across the application
  • Supports validation of configuration at startup to catch issues early
  • Environment-specific configuration (e.g., Development, Staging, Production)
  • Avoids hardcoded values, improving flexibility and deployment portability
  • Easy to extend with new settings without impacting existing functionality

Security

Authentication & Authorization

  • Uses JWT (JSON Web Tokens) for stateless authentication
  • Supports OAuth2 / OpenID Connect flows
  • External identity providers implemented via abstraction layer
  • Currently supports Google login, with extensibility for Microsoft and BankID

Token Strategy

  • Short-lived Access Tokens (10 minutes)
  • Long-lived Refresh Tokens (stored securely)
  • Refresh tokens are:
  • - Stored as hashed values in database
  • - Rotated on each use
  • - Revoked after usage to prevent replay attacks

Cookie Security

  • Tokens stored in HTTP-only cookies
  • Configured with Secure and SameSite=None
  • Prevents XSS access and supports cross-site scenarios

Secrets Management

  • No secrets stored in source code or configuration files
  • All sensitive data retrieved from Azure Key Vault
  • Environment variables used for runtime configuration

Domain-Level Security

  • Strongly typed IDs prevent incorrect data usage
  • Validation enforced at domain level ensures integrity

Logging & Observability

Structured Logging

  • Implemented using Serilog
  • Logs are structured with contextual data for better querying
  • Custom logging extensions standardize log format across application

Log Destinations

  • Console logging for local development
  • Integrated with Azure Application Insights

Request Tracing

  • Automatic request logging via middleware
  • Includes request path, response status, and execution time
  • Correlation using trace identifiers for distributed tracing

Custom Telemetry

  • Custom traces sent using TelemetryClient
  • Used for tracking key application flows and important events

Debugging & Diagnostics

  • Detailed logs for external API calls and database operations
  • Supports troubleshooting production issues efficiently

Error Handling

Global Exception Handling

  • Centralized middleware catches all unhandled exceptions
  • Prevents leaking internal details to clients
  • Logs full exception details to Application Insights

Standardized Error Responses

  • Uses ProblemDetails (RFC 7807) for all error responses
  • Consistent structure across the entire API
  • Includes status code, title, and error details

Result Pattern

  • All operations return Result<T> instead of throwing exceptions
  • Separates success and failure explicitly
  • Improves readability and control flow

Error Categorization

  • Custom error codes (e.g. NotFound, Unauthorized, ExternalServiceFailure)
  • Mapped to appropriate HTTP status codes in controllers

Resilience

  • External API failures handled gracefully
  • Retry and circuit breaker policies reduce cascading failures

Fail-Fast & Validation

  • Input validation using FluentValidation
  • Invalid requests rejected early in the pipeline
  • Domain invariants prevent invalid state

Presentation Layer

General API Design

  • Built using ASP.NET Core Web API
  • Follows RESTful principles with resource-based endpoints
  • Endpoints are versioned using query string versioning
  • Fully documented using Swagger / OpenAPI

Controller Design

  • Controllers are intentionally kept thin
  • All business logic is delegated to application services
  • Controllers are responsible for:
  • - Request mapping
  • - Response formatting
  • - Translating domain results into HTTP responses

Validation

  • Input validation implemented using FluentValidation
  • Validation is automatically triggered via pipeline integration
  • Ensures invalid requests are rejected early

DTO Design

  • Clear separation between Request DTOs and Response DTOs
  • No domain entities exposed directly to clients
  • DTOs implemented as records for immutability

Features

  • Supports paging, sorting, and filtering on list endpoints
  • ETag-based concurrency support in update operations
  • Consistent response handling via centralized Result pattern

Middleware

  • Custom middleware for:
  • - Global exception handling
  • - API version enforcement
  • - Request logging

Domain Layer

Core Principles

  • Pure domain layer with no external dependencies
  • Implements Domain-Driven Design
  • Encapsulates all business rules and invariants

Entities & Value Objects

  • Entities represent core business concepts (e.g. Movie, Person, User)
  • Value objects used to model domain concepts with validation
  • All invariants enforced at creation time

Strong Typing

  • Uses strongly typed IDs (e.g. MovieId, PersonId)
  • Implemented using record struct
  • Prevents accidental misuse of primitive types

Immutability & Safety

  • Value objects are immutable
  • Entities expose controlled mutation through methods
  • Ensures domain consistency at all times

Error Handling

  • Uses Result pattern instead of exceptions
  • Domain errors are explicit and strongly typed
  • Centralized error definitions for consistency

Benefits

  • Avoids primitive obsession
  • Improves readability and maintainability
  • Makes business logic testable and predictable

Infrastructure Layer

Database & ORM

  • Uses Entity Framework Core
  • Code-first approach with migrations
  • Hosted on Azure SQL Database

Repository Pattern

  • Separation of Read and Write repositories
  • Read repositories optimized for queries (projections, no tracking)
  • Write repositories handle persistence and domain updates

Performance Optimization

  • Uses AsNoTracking for read queries
  • Projects directly to DTOs to avoid unnecessary loading
  • Efficient querying using LINQ and filtering

Concurrency Handling

  • Implements optimistic concurrency
  • Uses RowVersion in database
  • Converted to ETag for client communication

External Integrations

  • External APIs accessed via HttpClientFactory for efficient connection management and DNS refresh handling
  • Resilience implemented with Polly (retry, circuit breaker, timeout policies)
  • Retry policies and circuit breakers prevent cascading failures and improve system stability
  • SemaphoreSlim used to limit concurrent outbound requests and protect downstream services
  • Timeouts enforced to avoid hanging requests and resource exhaustion
  • Structured error handling and fallback responses for degraded external dependencies
  • External endpoints and policies configurable via centralized configuration

Caching

  • In-memory caching using IMemoryCache
  • Configurable TTL (Time-To-Live) to control cache duration
  • In a production-ready environment, this would be complemented with Cache Invalidation
    on data updates or deletions, along with version-based consistency to prevent stale data.

Dependency Injection

  • All services registered via centralized DI configuration
  • Loose coupling between layers via interfaces

Infrastructure Services

  • Password hashing using BCrypt
  • JWT token generation and validation
  • Refresh token lifecycle management
  • DateTime abstraction for testability

Application Layer

Responsibilities

  • Coordinates use cases and orchestrates business workflows
  • Acts as a boundary between the presentation layer and domain layer
  • Does not contain business rules, but delegates them to the domain layer

Structure

  • Organized around use cases (e.g., commands and queries)
  • Uses patterns like CQRS to separate read and write operations
  • Handlers process requests and coordinate domain entities and services

Validation

  • Input validation handled using FluentValidation
  • Ensures only valid data reaches the domain layer
  • Validation rules kept separate from business logic for maintainability

Dependency Management

  • Depends only on domain abstractions, not infrastructure implementations
  • Uses dependency injection for loose coupling and testability

Transaction Handling

  • Coordinates transactions where required (e.g., unit of work pattern)
  • Ensures consistency across multiple operations

Cross-Cutting Concerns

  • Logging, validation, and error handling handled via pipeline behaviors or middleware
  • Supports clean separation of concerns and reduces duplication

Mapping

  • DTOs mapped to domain models.
  • Prevents leakage of domain entities to outer layers

Frontend Architecture & Design

  • Built as a modern React 19 + Vite SPA for fast development and optimized production builds
  • Feature-based folder structure (e.g. features/movies, features/cart) to improve scalability and maintainability
  • Clear separation between UI (components), data fetching (hooks), and domain models
  • Shared components and layouts centralized under shared/ to avoid duplication
  • Strong typing throughout using TypeScript strict mode to reduce runtime errors
  • Alias-based imports (@/) improve readability and avoid deep relative paths
  • Design favors composition and reusable components over tightly coupled page logic

State Management & Data Fetching

  • Server state managed using @tanstack/react-query for caching, background refetching, and request deduplication
  • Centralized QueryClient configuration (e.g. staleTime, retry policies) ensures consistent behavior across the application
  • Mutations automatically invalidate queries to keep UI in sync with backend state
  • Client-side state handled via React Context for cross-cutting concerns (Auth, Cart, Favorites)
  • Separation between server state and UI/local state avoids unnecessary complexity
  • Guest vs authenticated behavior handled transparently (e.g. cart stored in localStorage for guests, API for authenticated users)
  • Optimistic UI patterns used where appropriate to improve perceived responsiveness

API Layer & Integration

  • Centralized API client abstraction built on fetch, handling base URL, headers, and error handling
  • Automatic token refresh flow implemented for expired sessions using refresh cookies
  • Global 401 handler triggers logout and redirects to authentication flow
  • Strongly typed API contracts generated via OpenAPI (openapi-typescript)
  • Consistent API versioning via query parameters (api-version)
  • Error responses normalized into a unified ApiError model
  • Support for advanced scenarios such as ETag-based concurrency in update operations

Routing & Navigation

  • Client-side routing implemented using React Router v7
  • Route-based code organization aligned with feature modules
  • Protected routes implemented via ProtectedRoute component
  • Authentication state determines access to restricted pages (Profile, Orders, Favorites, Checkout)
  • URL-driven state (e.g. search queries, selected movie) enables deep linking and shareable URLs
  • Navigation includes dynamic UI elements such as cart badge and profile dropdown

User Experience & Interaction Design

  • Debounced search input reduces unnecessary API calls and improves performance
  • Split-view layout allows simultaneous browsing and detail inspection
  • Lazy loading of additional data (e.g. cast, reviews) optimizes initial load time
  • Immediate feedback via loading indicators, error messages, and success states
  • Cart badge dynamically reflects current item count for real-time feedback
  • Favorites system enables quick access and personalized browsing
  • Graceful handling of empty states (e.g. no favorites, empty cart)

Forms & Validation

  • Forms managed using react-hook-form for performance and minimal re-renders
  • Validation implemented with Zod schemas for type-safe validation rules
  • Custom validation logic ensures correct ranges and relationships (e.g. min/max values)
  • Input preprocessing and normalization (e.g. optional numbers, clamping values)
  • Error messages displayed inline for improved usability

Authentication & Session Handling

  • Authentication handled via AuthContext with centralized session management
  • Supports email/password login, Google OAuth, and BankID integration
  • Session restoration on app startup using refresh tokens
  • Guest data (e.g. cart) automatically merged into user account upon login
  • Secure cookie-based authentication (no tokens stored in localStorage)

Performance & Optimization

  • Built with Vite for fast dev server startup and optimized production builds
  • Sourcemaps enabled for debugging production issues
  • React Query caching reduces redundant network requests
  • Component-level state minimizes unnecessary re-renders
  • Code structured to support future lazy loading and code splitting
  • Efficient list rendering and sorting logic for large datasets

Tooling & Developer Experience

  • Strict TypeScript configuration enforces high code quality
  • ESLint and Prettier ensure consistent code style
  • OpenAPI-based type generation keeps frontend aligned with backend contracts
  • Modular structure improves onboarding and long-term maintainability
  • Environment-based configuration using Vite env variables
  • Clear separation between development, build, and preview workflows
